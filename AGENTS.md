# AGENTS.md

Guidance for coding agents working in this repository.

Weft is a local-first macOS (26+) menu bar time tracker written in Swift 6 / SwiftUI / SwiftData. It classifies activity with rules plus Apple's on-device Foundation Models, or an OpenAI-compatible API if the user sets one up. By default nothing leaves the Mac.

## Commands

`Weft.xcodeproj` is generated by XcodeGen from `project.yml` and git-ignored. Regenerate it after adding, removing or renaming files under `App/`, or after editing `project.yml`.

```sh
xcodegen generate
xcodebuild -project Weft.xcodeproj -scheme Weft -derivedDataPath build/DerivedData build
open build/DerivedData/Build/Products/Debug/Weft.app
```

Tests live only in the `WeftKit` package and use Swift Testing (`@Test`, `#expect`), not XCTest:

```sh
cd Packages/WeftKit
swift test                                                   # all unit tests
swift test --filter SessionEngineTests                       # one suite
swift test --filter "SessionEngineTests/startAndExtend"      # one test
WEFT_AI_TESTS=1 swift test --filter FoundationModelsHarness  # real on-device model (needs Apple Intelligence)
WEFT_AGENT_LOG_TESTS=1 swift test --filter AgentLogHarness   # parse this Mac's real Claude Code, Codex and pi logs
WEFT_STORE_COPY=/tmp/copy/Weft.store swift test --filter AgentStoreHarness  # migrate a store copy and fill it from real logs
```

The Debug build uses the real store in `~/Library/Application Support/Weft/`. Before trying a schema change there, back it up; `AgentStoreHarness` shows how to test against a copy made with `sqlite3 -readonly … ".backup …"` instead.

Signing: `Config/Base.xcconfig` signs ad hoc by default, and optionally includes the git-ignored `Config/Local.xcconfig` (copy it from `Local.xcconfig.example`). With ad hoc signing, macOS drops the Accessibility grant after every rebuild, so window titles stop showing up until you grant it again.

Releases: `scripts/release.sh` builds a Developer ID–signed, notarized `build/release/Weft-<version>.dmg` for direct download. Bump `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in `project.yml` first. The one-time setup (Developer ID certificate, and the `asc` CLI signed in with an App Store Connect API key for notarization) is described at the top of the script.

The app icon (`App/AppIcon.icon`, Icon Composer format) is generated by `python3 scripts/make-glass-icon.py`. Don't edit the SVGs by hand.

Website: `site/` is the static marketing site, with no build step, `index.html` in English and `zh/index.html` in Chinese. The two pages share `assets/`, so a change to a page's text needs making in both. `assets/site.js` draws the product mockups (Today, the menu bar popover, agent sessions) in HTML from made-up data, copying the app's own views, so update them when those views change. The site makes no third-party requests and the footer says so; keep it that way. Preview it with `python3 -m http.server -d site`, since the icon sprite doesn't load from `file://`. Pushing changes under `site/` to `main` deploys it to GitHub Pages (`.github/workflows/pages.yml`), served at https://weftapp.org.

## Architecture

There are two layers:

- **`Packages/WeftKit`**: all logic (tracking, storage, classification, metrics, sessions), with no UI. Put anything you want to unit test here.
- **`App/`**: the SwiftUI shell. `LSUIElement` app with a menu bar popover (`MenuBar/`), a main window (`Main/`) and full-screen break/blocker overlays (`Overlays/`). It also handles the `weft://` URL scheme (in `WeftApp.swift`).

`App/Support/AppModel.swift` is the composition root. It creates the single SwiftData `ModelContainer` and every long-lived service, and connects them in `wire()`. Services don't know about each other directly; they talk through closures (`onStart`, `onEnd`, `requestRecheck`, `onIncidentChange`, `notifier.onAction`) and through tracker listeners. All services are `@MainActor @Observable` and share `container.mainContext`.

### Data flow

1. **Tracking** (`Tracking/`): `ActivityTracker` is event-driven to save power. `WindowEventObserver` (AX/workspace notifications) triggers a sample when the app, window or title changes. On top of that there's a 60 s heartbeat, a one-shot idle timer and a slower check while the user is away. There is no fast polling loop; keep it that way. `TitleChangeThrottle` mutes noisy title changes, such as terminal spinners. `BrowserURLProvider` reads the tab URL via Apple Events. Each sample builds an `ActivityContext`. `TrackingStateMachine` is pure (no AppKit or storage, unit tested) and turns samples into `.open/.extend/.close` effects, which the tracker applies to `ActivitySegment` records. Idle (5 min), sleep, lock and pause close the segment. Meetings are exempt from the idle cut. Every sample also goes out as a `TrackerSample` to listeners (break reminder, work hours, distraction guard).
2. **Classification** (`Classification/`): `ClassificationService.classify` tries, in order:
   1. `RuleEngine` (user rules + about 360 `BuiltinRules`). Built-in bundle-ID rules don't apply to a tab with a domain, so a browser's own "browsing" rule only covers tabs without a site; unknown sites go on to the model.
   2. the cached AI answer, keyed by `ActivityContext.classificationKey` (bundle ID, plus the domain for browsers)
   3. a background queue to `AIClassifying`, which gets up to five of the app's or site's most-used titles (`TitleSummary`). In the app that's a `ModelRouter`, which forwards to `FoundationModelsClassifier` or `OpenAICompatibleClassifier` (Chat Completions), whichever **Settings → Model** picks; `AppModel.applyModelChoice` swaps it. Both share their prompts through `ModelPrompts`. The API key lives in the keychain, everything else in `Preferences`.

   While a segment waits on the model, it is stored as `uncategorized` with source `.pending`, and gets patched in place when the answer arrives. When there is no model, or the call fails, the segment gets source `.guess` and a category from `CategoryGuess` (the app's App Store category, or words in the site's domain). `retryPending` asks the model again about pending and guessed segments, and its answers replace guesses. Review (`Main/ReviewView.swift`, listed by `ReviewList`) shows what no rule covers. Keeping the model's answer there sets `reviewed` on its `AIClassificationRecord` instead of adding a rule; keeping a guess or picking another category adds a rule. Apps and sites used under 5 min in the last 30 days are listed apart and left out of the badge. Adding or deleting a rule reclassifies matching past segments, except `.manual` ones. At launch, `Maintenance.run` lets newer rules override old AI answers and guesses, and reclassifies sites that older versions filed as built-in browsing.
3. **Metrics** (`Metrics/`): pure functions over segments. `ActivityBlocks` builds the activity log rows and folds short detours into them. `TimeEntries` builds the overlapping per-category "work streams" on the Today timeline: same category within 30 min forms one stream, and only streams of 10 min or more count as significant. `AgentBlocks` groups an agent session's spans by the same rules. `DayTimeline` lays streams and agent blocks out together, with no separate agent lane, using `ColumnLayout`: calendar-style columns, where each item widens into columns to its right that stay free while it lasts. `DayMetrics` computes the Focus Score.

   Reports (`Main/ReportsView.swift`) covers a week, month, year or all of history (`ReportPeriod`), with agent work by project above the user's own time by category. A year is far too many segments to read on every render, so finished days come from `DaySummaries` (`Storage/DaySummaries.swift`). It keeps one `DaySummary` per day holding a `DayRollup`, which has the day's `DayMetrics` without waiting on agents, plus the user's presence and distracting intervals. Waiting is worked out from those and the current `AgentSpan`s on each render (`DayRollup.daily`), so agent changes never make a day stale. A background `DaySummaryBuilder` adds days up, newest first. It reads SwiftData's persistent history from a saved token, and rebuilds any day whose segments changed since: a rule, the model's answer, an edit. A day is also rebuilt when its `inputs` (category flags, time zone, version) differ. The day still going is computed live. A lost or expired token means rebuilding everything.
4. **Descriptions**: `TimeEntryService` queues finished streams for a one-sentence description from the model, cached in `TimeEntrySummary` by `TimeEntry.key` (category + start). `AppModel` runs it every ~5 min.
5. **Sessions** (`Sessions/`): `SessionEngine` handles Focus, Meeting and Break sessions. `DistractionGuard` triggers the blocker overlay when the user stays in a category marked `blockInFocus` during a focus session. `Reminders` holds the break and work-hours monitors, and `Notifier` wraps `UNUserNotificationCenter`.
6. **Agents** (`Agents/`): records when coding agents worked, from the logs they keep (`~/.claude/projects`, `~/.codex/sessions`, `~/.pi/agent/sessions`). It's a pipeline:
   1. `AgentLogScanner` (off the main actor) reads each log from a saved byte offset.
   2. `ClaudeCodeLogParser` / `CodexLogParser` / `PiLogParser` turn lines into `AgentLogEvent`s. They pick lines by prefix and decode only the few that matter, since the logs run to tens of megabytes.
   3. The pure `AgentTurnBuilder` assembles turns from them.

   A turn runs from a prompt to the agent's end marker, so the hours a session sits waiting for the user between turns never count. Inside a turn, waits for the user's permission or answer are cut out, and so is silence longer than `agentSilentGapMinutes`. What's left is stored as `AgentSpan`s.

   While a turn is open, its cursor stays at the turn's first line, so the whole turn is read again once it ends and no parser state is persisted. Read Again (`reimport`) only forgets the cursors: a log read from the start replaces its own spans, and spans from logs the agents have since deleted (Claude Code removes old ones) stay, since Weft has the only copy. `AgentActivityService` re-reads logs when FSEvents reports a change (no polling). It treats a session as working right now when Claude Code's `~/.claude/sessions/<pid>.json` says `busy`, or, for other agents, when an open turn had activity in the last 5 min.

   `HAPISync` (`Agents/HAPI/`) is the authoritative source for every session its hub has recorded, including sessions on this Mac. Every 5 min it runs `hapi usage --json` and stores the turns minus permission waits as `AgentSpan`s keyed `hapi:<id>`. The app awaits the first bounded sync attempt before starting native scans. Local logs are only a fallback for sessions with no HAPI history. After a successful import, `HAPISessionLink` persists the local/HAPI identity and native spans for that whole session leave the statistics; there is no interval clipping or mixing with native-only older history. The scanner skips owned logs (including child threads), reading only identity headers when necessary, and rejects in-flight results if HAPI took ownership during the scan. Empty incremental reports, offline restarts, disabled syncing and native reimports do not revoke ownership. A legacy link without imported HAPI history does not suppress fallback. `HAPIBinaryLocator` finds the native `hapi` binary behind the Node launcher; `ProcessRunner` drains both pipes as output arrives. HAPI before 0.30 started Claude for unknown commands, so `HAPISync` checks `hapi --version` first.

   `AgentMetrics.waiting` finds time the user spent waiting on agents: away (up to `agentWaitingCapMinutes` after their last activity) or in a distracting category while an agent worked. `DayMetrics.trackedTime` adds the away part to `activeTime`, and the work-hours target counts it. The Focus Score never sees agent time.

   Projects (`Agents/Projects.swift`): `Projects.assign` files each `AgentSession` under a `Project` once, while its folder still exists, and never again, so removing a worktree doesn't move its history. It runs at launch (`Maintenance`), after a scan and after a HAPI sync. `ProjectResolver` reads `.git` files without running git. A subfolder counts as its repository and a worktree as its main checkout. The project is keyed by the normalized origin remote (`git:github.com/owner/repo`, credentials stripped) so clones match, otherwise by `folder:<path>`. Folders on other machines can't be looked into, so they're `folder:<host>:<path>`. Temporary folders and the home folder get `Project.none`. `ProjectMetrics` counts a project's time while at least one of its sessions works, so parallel sessions count once. Reports shows projects from `AgentSpan`s alone, with no rollup, since a year is a few thousand spans. Each project keeps the `colorSlot` it was given, so its chart color doesn't depend on its rank.

### Storage

SwiftData models live in `Storage/Models.swift`, and the schema list is `WeftSchema.models`; add every new `@Model` there. `ActivitySegment` is only ever the user's own foreground time, and everything that reads it assumes so. Agent work lives in `AgentSession`, `AgentSpan` and `AgentLogCursor`, with `HAPISessionLink` for confirmed local/HAPI associations and `Project` for what sessions worked on. `DaySummary` is a cache that can be rebuilt at any time; deleting it loses nothing. Native session metadata and cursors remain available for identity after HAPI takes ownership, but their work spans are removed. These store identifiers, titles, project folders and times but never prompts or replies. The store is at `~/Library/Application Support/Weft/Weft.store`. Enums are stored as raw strings (for example `classificationSourceRaw`) so that `#Predicate` can filter on them. Keep that pattern when adding filterable enum fields. Categories are seeded from `CategoryDefinition.defaults` and referenced everywhere by string `key`.

### Testing patterns

Tests use `WeftSchema.makeContainer(inMemory: true)` and a stub `AIClassifying` (for example `NoAI` in `SessionEngineTests`) so they never call the real model. Code that depends on AppKit or Accessibility goes behind pure types, like `TrackingStateMachine` and `TitleChangeThrottle`, which are what the tests cover.
